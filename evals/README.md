# 行为评测场景

这些场景用于人工或独立代理验证协作行为，定义位于 [scenarios.json](scenarios.json)。它们是评测规格，尚未产生跨模型独立评测结果。发布结构检查通过不等于这些行为全部通过。

## 如何执行

1. 在隔离的测试项目中加载本仓库的 `skills/brief-to-ui/`，每个场景使用新会话。
2. 将对应的项目背景、当前阶段和用户请求提供给所用 AI 工具。
3. 收集完整回答、提出的问题、生成的预览，以及文件改动记录。
4. 按 `success_criteria` 和 `failure_signals` 人工判定通过、部分通过或失败，说明观察依据。
5. 记录模型标识、日期、工具能力、skill 版本、输入与结果。模型和工具配置变化时重新判断，不将自评改写成独立结果。

在“尚未批准实现”的场景中，检查目标业务文件确实没有改变；仅阅读回答里的承诺不足以通过。隔离预览文件可以生成，但不能冒充业务实现。

## 看哪些结果

- 是否帮助用户说清主要任务，而不是只给长问卷。
- 是否准确区分假设、建议和事实。
- 是否在需要时提供具体可确认方案，而不是提前写入业务文件。
- 是否保留已有技术栈、关键字段和认可的视觉基线。
- 是否能保留有用途的卡片和必要文案。
- 是否在批准后完成对应工作，避免重复确认或扩大范围。

视觉质量另行比较任务完成、分组识别、操作发现、可读性与一致性。优先采用同一需求和数据的多次生成与盲评，不依据一次截图给所有模型或所有场景排名。
