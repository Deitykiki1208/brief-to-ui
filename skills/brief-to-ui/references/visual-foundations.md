# 视觉基础：规则、条件与检查

这里结合已读资料与 Deityki 默认配置。字号数量、细边框和默认配色是个人要求，不作为行业通用标准。项目覆盖规则见 [profiles.md](profiles.md)，后台容器与密度取舍见 [admin-patterns.md](admin-patterns.md)。来源编号见 [sources.md](sources.md)。

## 信息层级与密度

先确定阅读顺序与主要动作，再用位置、分组、字号和强调程度表达主次。同一层级使用相近的表现；强调要有明确对象。把邻近、相似与熟悉模式当作帮助理解的启发式，不当作保证转化或效率的“定律”。[S10]

留白由关系决定：同组内容靠近，跨组留出分隔，边缘与列保持对齐。密度取决于任务；比较多列数据时保留必要信息，宣传与阅读界面可以放宽节奏。上述是本 skill 的综合判断，不是某个来源的固定布局标准。

减少用户为继续操作而被迫做的无必要选择。主操作、合理默认值和信息优先级应清楚，必须发生的选择放在自然的决策节点。删除重复标题、次要标签和对布局已经表达清楚的内容的解释，避免为每个区域补一行说明。

对齐先统一容器边缘、文字基线、数字列、图标与控件间距，再检查光学中心。图标可在固定图标框内作小幅视觉修正，避免靠全局偏移破坏整行对齐。用真实字体、图标和不同长度文本确认。

检查：去掉装饰后能否辨认页面重点？两个同样重要的内容是否被无理由地赋予不同样式？主操作是否被无关颜色、图案或反复的大标题淹没？

## 字体与文字

从正文的可读性开始，调整字体、大小、行高和行宽，再建立标题、正文、辅助文字的层级。[S05] 每个页面优先三种字号、最多四种，最小 12px；正文和主要操作按实际人群与设备选用易读尺寸，不将最小值作为默认正文。优先通过字重、颜色、行高和间距区分更多层级。长标题与真实内容要能自然换行。Web 的尺寸按 CSS px 表达，其他平台换算并在实际设备上检查，保留用户字号缩放能力。

不要直接把英文字符行宽套到中文，也不要把作者偏爱的付费字体当作前提。按实际语言、设备、字体可用性和授权选择字体。较轻字重与低对比不天然更高级。

检查：使用实际中文与英文混排、长标题、单位、日期和大数字，确认截断、换行及对齐。数据列保持便于比较的对齐和格式，不靠字体装饰解释数值意义。

## 界面文案与图标

使用当前界面人群熟悉的行业用语和明确动作，长度符合任务，不随意造词或过度口语化。标题、按钮、导航和短标签通常不加句末标点；正文、多句说明、错误与操作结果保留必要标点。

不用 `.／·／•` 等点号装饰性分隔文案，改用间距、换行或分组；小数、版本号、网址、邮箱、文件名与其他含义必需的点号保留，不进行全局字符替换。此规则针对界面文案，不禁止文档正常的列表语法。

删除不帮助用户理解或完成任务的说明及次要标签；保留字段名称、单位、错误原因、操作结果和完成任务所需的提示，不将必要信息藏进 Tooltip。评审时说明删除或精简的依据，不用额外说明文字补救不清晰的布局。

默认不使用 emoji。统一使用 Lucide 等风格一致的开源 UI 图标，核对许可证、线宽、尺寸、语义与视觉中心；纯图标控件有可理解的名称，装饰图标不重复朗读。[S17]

## 颜色与对比

区分品牌强调、交互、选中、成功、警告和错误的用途，再选具体颜色。相同语义保持一致，状态还需要文字或图形等线索；这是本 skill 的综合设计规则。

界面背景、文字、图标、边框、交互与状态色统一由语义变量映射 Radix Colors；不散落手写色值或混用另一套独立调色板。按需要建立浅色、深色与透明色映射。Radix Colors 是颜色体系，采用它不要求再引入 Radix Themes 或替换现有组件底层。[S14]

| 色阶 | 主要用途 |
| --- | --- |
| 1–2 | 页面与柔和背景 |
| 3–5 | 组件默认、悬停、按下或选中背景 |
| 6–8 | 分隔线、组件边框及较强边界 |
| 9–10 | 实色操作区及其悬停背景 |
| 11–12 | 次要文字与主要文字 |

色阶用途是起点，最终组合仍需验证。Sky、Mint、Lime、Yellow、Amber 的 9–10 阶应配深色前景，不机械将所有强调按钮设成白字。焦点使用足够明显的颜色与形状，不能只依赖低对比细边线。shadcn/ui 的 background、foreground、primary、border 等语义变量映射到这些色阶，覆盖默认调色板而不另建平行主题。[S14, S15]

Color.review 可帮助检查前景与背景组合。[S07] 按 WCAG 2.2 SC 1.4.3 的适用条件，普通文字的最低对比为 4.5:1，大字为 3:1；标志、纯装饰及不活动控件等有例外。大字条件和例外查当前标准，不靠视觉猜测。[S12]

文字对比通过不代表控件边界、焦点或整页可访问性都通过。浅色、深色以及覆盖在图片/透明材质上的文字分别检查；不要用过低对比制造“简约”。

## 响应式与尺度

Utopia 展示在小、大视口端点之间协调字号与间距的思路。[S06] 使用有限字号与间距变量，并在需要时连续变化；每个实际视口仍遵守上述字号数量与最小尺寸，不为每个元素独立引入一种字号或断点。

连续字号不能代替布局适配。导航、表格、动作区和文本换行仍需在实际宽度下检查。小屏不是把所有元素等比例缩小；先维持阅读顺序与主要动作可达性。

检查：窄屏、宽屏、内容极值及中间宽度是否出现重叠、孤立标题、过长行或无法到达的操作？字号缩放后容器是否仍能承载内容？

## 表面与装饰

先使用对齐、留白和信息分组表达结构，再判断是否需要边框、圆角、阴影、模糊、渐变或纹理。卡片用于独立对象、操作或有明确边界的内容，避免重复嵌套；默认不使用卡片左侧的装饰性彩线。清晰分组优先于减少卡片数量，不能因追求“零卡片”而把不同任务铺成缺少边界的整页内容。

移除容器前检查：去掉边框后，用户能否同样快地辨认这组内容的标题、范围与操作？若需要扩大空白、增加标签或重新解释才能补救，保留适量容器通常更合适。已选方案的局部优化一次改变一个主要因素，保留原版以供比较。

普通边框与分隔线默认 0.5px，用统一变量管理，并检查不同设备像素比、缩放与浅深背景的清晰度。键盘焦点指示单独设计，保证可辨识；不为实现细线缩放整个交互控件或破坏点击区域。

圆角和阴影按功能设置，统一少量等级，不将全圆角、悬浮阴影当作所有组件默认值。嵌套曲线尽量保持同心：等距内缩、相同边界定义时，内圆角以 max(0, 外圆角 − 内缩距离) 为起点，再考虑边框及实际视觉结果，不将同一圆角数值直接套在每一层。阴影用于确有层次关系的浮层等场景。

在灵感库中比较实际页面时，记录可迁移的结构与细节，以及不适合当前任务的部分。未检查真实交互的截图只提供视觉证据。
