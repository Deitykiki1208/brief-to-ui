# 方法与可配置偏好

Brief to UI 的方法是整理需求、研究、预览确认、局部迭代和如实验收。Deityki 的配色、字号、边框和库组合是默认配置，其他使用者可以替换这些偏好而保留方法。

## 读取顺序

1. 用户当前明确要求与已批准范围。
2. 已提供的项目规范和根目录 UI_PROFILE.md；与实际约束冲突时指出影响并澄清，不静默合并矛盾规则。
3. 已有设计系统、组件库、数据契约与技术栈。
4. 本 skill 的 Deityki 默认配置。

读取已有配置不等于获准修改它。不为应用个人主题而擅自迁移框架、替换成熟组件或重写整页；需要变化时纳入可确认方案。新项目没有明确偏好时使用下列默认配置，按场景解释取舍。

## Deityki 默认配置

| 项目 | 默认值 | 适用边界 |
| --- | --- | --- |
| 场景 | 中文业务后台与内部工具 | 其他界面重新判断任务和信息密度 |
| 分组 | 适量容器、统一对齐、克制装饰 | 清晰分组优先，不以零卡片为目标 |
| 颜色 | Radix Colors 语义色阶 | 现有系统与项目明确主题优先；检查真实组合对比 |
| 组件 | 新 React Web 使用 shadcn/ui Nova | 不为此改用 React，现有系统先核对迁移范围 |
| 图标 | Lucide，默认不使用 emoji | 统一许可、线宽、尺寸与语义 |
| 字号 | 每页优先三种、最多四种、最小 12px | 保留用户字号缩放；正文按实际人群选易读尺寸 |
| 边框 | 普通边框与分隔线 0.5px | 焦点单独处理；核对设备与缩放清晰度 |
| 动效 | 默认减少，必要时 ease-out、250ms 起调 | 不统一延迟反馈，保留减少动态效果支持 |
| 文案 | 成熟中文用词，无冗余解释和装饰性点号 | 保留字段、单位、错误、结果和语义必需标点 |
| 依赖 | 同一职责限制重复库，按需引入 | 复杂动效、分栏、拖拽与共享状态有需求再采用 |

## 项目覆盖示例

用户可以用普通文字提供同样的信息，不必创建配置文件。若希望保存为 UI_PROFILE.md，可在明确授权后写入：

```markdown
# 项目 UI 偏好

- 使用人群：运营主管，在电脑上批量处理业务
- 主要任务：定位异常、审批、对比多行数据
- 已有技术：Vue 和现有组件库，保持不变
- 配色：沿用品牌主题，优先保留语义变量
- 密度：紧凑，确保常用操作可发现
- 分组：保留有意义的卡片，去掉重复嵌套
- 动效：只保留必要反馈
- 确认流程：先看示例图，明确确认后再修改页面
- 必须保留：业务字段、权限和统计口径
```

配置里的“紧凑”“沿用品牌”等仍需转成可审阅方案，不将模糊形容词当作实施细节已确认。
