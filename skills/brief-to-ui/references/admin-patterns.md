# 中文业务后台的结构判断

先确定用户要判断什么、接着执行什么，再选择布局。优先级为：任务与数据正确 → 分组和操作清晰 → 层级与一致性 → 装饰克制。下面是判断依据，不是必须出现在每页的模块清单。

## 按任务选择页面结构

| 页面 | 首要任务 | 建议结构 | 常见误用 |
| --- | --- | --- | --- |
| 总览 | 发现异常与待办，进入处理 | 少量关键指标、待处理入口、相关列表；趋势仅在支持决策时加入 | 先堆图表和快捷入口，异常藏在下方 |
| 业务列表 | 找到、比较、筛选与批量操作 | 标题与主操作、相关筛选、表格、明确选择状态与分页 | 将有行列比较关系的数据全部拆成卡片 |
| 表单 | 准确输入并完成提交 | 按业务关系分组、持久标签、字段附近错误、明确提交反馈 | 为每个字段写解释、错误后清空输入 |
| 详情 | 理解对象状态与下一步 | 对象身份、状态、关键字段、相关记录和有权限的操作 | 把所有字段等权排成网格或另加一张总览图 |
| 审批 | 判断依据充分，明确同意或退回 | 申请内容、必要凭证、流程状态、当前操作与结果 | 用流程装饰替代依据，退回后不说明后续 |

用户、状态、时间范围和统计口径必须明确。不要把模拟 KPI、硬编码分类或生成图片当作真实业务接口契约。日期、金额、单位和负责人使用一致表达，标识与名称采用用户熟悉的用词。

## 保留什么卡片

- 保留能界定独立对象、独立操作、不同来源或阅读范围的容器，例如待审批事项与回款趋势分区。
- 同一组指标可以共用一个容器；去掉每个数字外面重复的小容器，不必再去掉这组指标的整体边界。
- 若内容在同一任务与上下文下连续阅读，优先使用标题、行距、细分隔线或表格，不为每段新建卡片。
- 不机械追求零卡片。移除容器后若标题归属、内容边界或操作对象变模糊，恢复适量边界。
- 阴影只表达实际层次；色块只表达必要状态或强调。避免卡片左侧装饰彩线、重复图标底板和每区一行副标题。

## 密度、留白和对齐

围绕常用任务选用舒适或紧凑密度，同页同类控件保持一致。扩大留白不应把关键操作、异常和常用行挤出首屏；不要用大量空白换取表面简洁。小屏保留字段含义与主操作，不把所有控件等比缩小。

统一内容左缘、标题与区域关系、图标框、表格基线和动作列。数值按比较需要对齐；长中文项目名、状态、金额、日期和混排字符必须用实际内容检查。光学微调不能造成整行控件错位。

## 文案和交互的取舍

布局能说明的内容不重复解释；标签、单位、错误、权限与操作结果必须清楚。必要选择放到用户自然需要决定的位置，提供有依据的默认值。删除无意义确认时，保留真实业务与风险需要的确认或撤销能力。

状态反馈必须清楚，但不要求每次都动画、弹窗或增加一段成功说明。可使用按钮加载、行状态更新、简短反馈或定位到结果；同时检查用户能否理解变化。

## A 与 A2 的反例

一次后台首页示例中，A 使用适量分区容器，A2 去掉全部外围卡片、图表填色和图标。用户更喜欢 A。已知事实仅是这次视觉选择；原因判断是 A 的分区边界可能更利于扫描，并非经可用性测试得到的结论。

可复用的经验：优化时同时保留基线与改版，比较分组清晰度、信息扫描、操作发现和视觉噪声；不要把“更少卡片”直接写成验收目标，也不据此认定所有后台都应使用相同卡片布局。
