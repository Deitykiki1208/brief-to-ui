# 研究参考与默认组件选择

从当前任务出发寻找官方文档、成熟产品和相关开源项目。参考来源和阅读边界见 [sources.md](sources.md)。公开版只提供自己的规则归纳与链接，不附带原始目录抓取快照。

## 先研究再提出方案

新需求在实质设计或开发前主动查找相关官方示例、成熟产品与优秀高 star GitHub 项目，通常筛选 3–5 个最相关参考。为每个参考说明链接、值得学习的结构或行为、适用条件及不应照搬的部分；核对近期维护、演示、技术适配、许可证和依赖。Star 是发现线索，不是质量、可用性或安全保证。已有研究足够时复用，简单修改无需重复搜索。

用户可以只说简单想法；助手负责将参考转成需求摘要和可审阅方案，而不是要求用户预先指定所有库。参考图片只用于确认视觉方向，真实交互需要独立验证。

## 新 React Web 项目的默认组合

以下是 Deityki 默认配置的选型，按实际功能引入，不一次性安装全部依赖。项目已有设计系统、用户明确要求及 [profiles.md](profiles.md) 中的项目覆盖优先。现有项目先检查框架、已安装库、组件底层、版本、样式接口、维护与许可证；替换或迁移纳入待确认方案，不因本规范擅自改用 React。

| 职责 | 默认选择 | 引入边界 |
| --- | --- | --- |
| 组件与视觉风格 | shadcn/ui Nova [S15] | 组件源码可控，统一风格；核对当前 preset、底层和现有项目兼容性 |
| 界面配色 | Radix Colors [S14] | 映射同一组语义变量，不因配色额外安装 Radix Themes |
| 图标 | Lucide [S17] | 统一图标系列与线宽，按需导入，不使用 emoji |
| 复杂动画 | Motion [S16] | 简单反馈先用 CSS/平台能力，确有必要才引入，保持克制 |
| 可调整分栏 | react-resizable-panels [S18] | 仅用于用户需要调整大小的面板，普通布局用 CSS Grid/Flex |
| 拖拽与排序 | dnd-kit [S19] | 核对当前框架入口及 API，保留键盘操作和必要替代入口 |
| 共享客户端状态 | Zustand [S20] | 仅在需要共享状态时使用；不将局部控件状态全部迁入全局 store |

同一职责尽量只有一套实现。复用现有组件，避免并行引入多套 UI、图标、动效、拖拽或状态管理方案。升级与新增依赖需有具体功能理由，核对包版本和重复依赖；本 skill 不锁定跨项目的统一版本号。采用默认组件不能替代整页状态、内容与交互检查。

## 组件选型

先看现有平台及组件能否满足交互需求，再看视觉是否可调整。按“适用框架 → 行为与状态 → 样式控制 → 内容与移动适配 → 依赖和维护 → 许可”进行相关核对。页面宣传里的“无障碍”“高转化”是待核实的声明。

可将 Radix 等无样式原语与整套视觉组件、复制代码式资源和装饰效果区分看待。选其中一种不意味着一定更高级。正式采用时读取当前官方具体文档，目录的一句话描述不足以决定。

## 研究入口

需要按钮与输入规则先查 UI Playbook；排版先查 Practical Typography 与 Utopia；卡片与表格结构先查 Inclusive Components；对比和目标尺寸以 W3C 标准核对。法律、行业合规或完整认证另按用户范围处理，本 skill 不承诺认证结果。

Learn UI 当前公开入口展示交互式设计工程读物，与旧目录的课程描述不完全相同；其作者汇编和示例需要追到原始文章才适合作为实现依据。Animations.dev、Devouring Details 等只读过公开介绍，不推定拥有付费章节内容。
